01Summary

The cache scanner in huggingface_hub reported files that Windows creates on its own, Thumbs.db and desktop.ini, as a corrupted cache. My original pull request, #4347, answered that with a whole new diagnostics command (437 lines). A question from the maintainer led me to reproduce the problem properly, which showed the real fix belonged in the scanner itself.

#4347 was closed. #4357 fixed the root cause in the scanner, with a regression test, was approved without changes, and shipped in v1.20.0.

02Context

huggingface_hub is the Python library that downloads and caches models from the Hugging Face Hub. Everything it downloads lives in a cache folder on your machine, and scan_cache_dir walks that folder to list what is there and how much space it takes. Anything that does not fit the expected layout is reported as a CorruptedCacheException warning.

Operating systems leave their own files in folders you open. The scanner already skipped macOS's .DS_Store inside a repo's refs and snapshots folders (the case reported in issue #2110). It did not know the Windows equivalents, and it did not apply the skip list at the top of the cache at all.

04Feedback

Less than four hours after #4347 was opened, the maintainer asked about the problem rather than the code: was this a real issue I had hit, and how would the command fix it?

After my reproduction (next section), the decision came the following morning, and #4347 was closed.

It was the right call. A diagnostics command for harmless warnings is code someone has to maintain for years, and it had never been requested.

05Reproduction

To answer the question honestly I built a realistic cache: a temp folder holding a real Hub file (hf-internal-testing/tiny-random-gpt2/config.json) in the normal cache layout. I confirmed it scanned clean, then added a single Thumbs.db at the cache root.

The scanner reported it as corruption. My command could show that warning more clearly and delete the file, but it did not stop the warning from happening. So I said so in the thread:

After looking deeper, this PR is not fixing the root cause of cache corruption itself.

Me, on #4347

06Root cause

scan_cache_dir loops over every entry at the top of the cache and hands each one to _scan_cached_repo. Before the fix, only the cache's own entries (.locks and CACHEDIR.TAG) were skipped there, so a stray file raised Repo path is not a directory. Inside a repo, files in snapshots were skipped only if they were in FILES_TO_IGNORE, which held just .DS_Store; anything else raised Snapshots folder corrupted. Found a file.

Because the exception ends the scan of that repo, the repo is recorded as a warning instead of a result. That is why a single Thumbs.db in a model's snapshots folder made the whole model disappear from hf cache ls.

For the specific root cause I reproduced, the smaller preventive fix would be to extend the scanner's existing .DS_Store ignore behavior to other harmless OS metadata files such as Thumbs.db and desktop.ini.

Me, on #4347

07The fix

#4357, opened Jun 12, 2026, 8:39 PM ET. Two changes in _cache_manager.py: the Windows names join the existing ignore list, and the top-level loop skips anything on that list.

The description said plainly what it does not do:

This keeps the fix intentionally small: it does not add a new repair command, and it does not try to handle broader cache corruption cases such as broken symlinks or interrupted downloads.

Me, in the description of #4357

08Tests

One regression test that needs no network. It builds a minimal valid repo, drops all three metadata files at the cache root, in refs and in snapshots, and expects a clean scan with exactly one repo.

10What I'd do again

  1. 01Answer the real questionThe review that mattered was not about code. It was: what real problem does this solve? Ask that before writing any code.
  2. 02Reproduce it before you defend itBuilding the failing case for real took a few hours and changed my whole PR. Without it I would have argued for the wrong fix.
  3. 03Fix the cause, not the reportThe original PR made the warning easier to read. The fix made the warning go away, because there was nothing wrong.
  4. 04Every line is a line someone maintainsMaintainers pay for every line you add, for years. Add what the problem needs and nothing else.
  5. 05Say what your PR does not doScope is part of the change. Writing down what I left out made the PR easy to say yes to.

What got this merged was the evening in between, when I stopped defending my code and checked whether it was needed.
